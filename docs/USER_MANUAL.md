# BUYMA 최저가 관리 프로그램 사용 안내

이 프로그램은 Google Sheets에 등록된 상품 URL을 읽어 BUYMA 공개 상품의 가격을 비교하고, 설정한 조건에 맞으면 BestShip 상품 가격을 BUYMA 공식 API로 변경합니다.

평소에는 메뉴형 프로그램을 사용하고, 정해진 시간마다 자동으로 가격을 확인하려면 예약 실행 프로그램을 켜 두면 됩니다.

## 1. 프로그램을 처음 받을 때 준비할 파일

실행 파일이 있는 폴더에 아래 파일과 폴더를 준비합니다.

```text
BUYMA/
├── BUYMA-Manager.exe
├── BUYMA-Scheduler.exe
├── config.yaml
├── .env
├── secrets/
│   ├── service_account.json
│   └── tokens.json
├── data/
├── logs/
└── reports/
```

- `config.yaml`: Google Sheets 주소, 탭 이름, BUYMA 판매자 정보와 브라우저 설정
- `.env`: BUYMA 로그인 정보, 타임세일 허용 여부, 예약 실행 시간과 가격 변경 단위
- `secrets/service_account.json`: Google 서비스 계정 인증 파일
- `secrets/tokens.json`: BUYMA 공식 API OAuth 토큰

실제 인증 파일과 `.env`는 프로그램을 전달받은 뒤 담당자가 직접 넣어야 합니다. 실행 파일에 인증정보가 들어 있는 것은 아닙니다.

## 2. 프로그램이 읽는 Google Sheets

### [2]최저가

가격 비교 대상 URL을 관리하는 입력 탭입니다.

| 열 | 프로그램에서 사용하는 값 |
|---|---|
| URL | 가격 비교를 시작할 BUYMA 검색/상품 URL |

프로그램은 실행할 때마다 이 탭을 다시 읽습니다. URL을 추가하거나 삭제하면 다음 실행부터 반영됩니다. 상품 가격이나 마지막 업데이트 날짜를 이 탭에 쓰지는 않습니다.

### api 가격변경 시트

가장 최근 실행의 결과를 보여주는 탭입니다. 다음 실행이 끝나면 새 결과로 바뀝니다.

상품별 현재 표시 가격, 경쟁 최저가, 변경 예정가, 적용 여부, 처리 결과, BUYMA 요청 UID 등이 들어갑니다.

### api 가격변경 시트 이력

실제 BUYMA 가격 변경 API 요청이 접수된 상품만 누적하는 탭입니다.

적용일시는 BUYMA Product API가 요청을 접수한 시점(실행 PC의 현지 시각)입니다. 상품 ID, 변경 전 가격, 변경 후 가격, 요청 UID도 함께 기록합니다. BUYMA API는 비동기 처리이므로 이 시각이 상품 화면에 가격이 최종 반영된 시각과 항상 같지는 않습니다. 단순 미리보기나 변경 조건에 맞지 않아 건너뛴 상품은 이 탭에 추가하지 않습니다.

### [6] 최저가 적용이력-공식API

실행 보고서 전체를 누적하는 탭입니다. 로컬 CSV 보고서와 같은 열과 행을 기록합니다. 가격 변경이 없는 미리보기 결과도 실행 보고서로 남을 수 있습니다.

### [5] 최저가 적용이력

기존에 사용하던 이력 탭입니다. 이 프로그램의 공식 API 보고서는 이 탭을 변경하지 않습니다.

## 3. 가격 비교와 변경은 이렇게 진행됩니다

1. `[2]최저가` 탭에서 URL을 읽습니다.
2. 각 URL을 BUYMA 공개 페이지에서 열어 상품 카드, 판매자, 상품 ID와 가격을 확인합니다.
3. BestShip 판매자 상품과 다른 판매자 상품을 구분합니다.
4. 경쟁 판매자 가격 중 가장 낮은 가격을 찾습니다.
5. 설정된 가격 차이와 최대 인하 폭을 적용해 변경 예정가를 계산합니다.
6. 실제 변경 모드에서는 판매자 편집 페이지에서 최신 상품 데이터를 다시 읽습니다.
7. BUYMA Product API에 상품 데이터와 새 가격을 보내고, 요청 결과를 보고서에 기록합니다.

API가 HTTP 201을 반환하면 BUYMA가 요청을 접수한 상태입니다. 상품 화면에 새 가격이 최종 반영됐는지는 BUYMA 상품 화면에서도 확인해 주세요.

## 4. 메뉴형 프로그램 사용

`BUYMA-Manager.exe`를 실행합니다.

| 메뉴 | 동작 |
|---|---|
| 1 | 전체 상품 가격 비교. 실제 가격은 바꾸지 않습니다. |
| 2 | 상품 ID 하나를 검색해 미리보기 후 해당 상품만 변경합니다. |
| 3 | 조건에 맞는 전체 상품 가격을 변경합니다. |
| 0 | 프로그램을 종료합니다. |

메뉴 1은 가격 비교 결과를 보고서로 저장합니다. 메뉴 2와 3은 가격 변경을 실행하기 전에 화면에서 변경할 가격을 확인합니다. 메뉴 3에서는 Y를 입력하면 진행하고, N을 입력하면 취소합니다. 별도의 긴 확인 문구는 사용하지 않습니다.

타임세일 상품 변경을 허용한 경우에는 일반 상품 처리 후 별도 후보 목록이 표시됩니다. 그 목록을 확인한 다음 Y/N으로 진행 여부를 선택합니다.

## 5. 가격 변경 기준

기본값은 `config.yaml`의 `app.price` 항목에서 설정합니다.

```yaml
app:
  price:
    delta: 10
    max_change: 50
```

- `delta`: 경쟁 최저가보다 몇 엔 낮출지 정합니다.
- `max_change`: 현재 실제 상품 가격에서 한 번에 내릴 수 있는 최대 금액입니다.

예를 들어 delta가 10이면 경쟁 최저가보다 10엔 낮은 가격을 계산합니다. 필요한 인하 폭이 max_change보다 크면 해당 상품은 변경하지 않습니다.

## 6. 타임세일 상품

`.env`에서 설정합니다.

```env
BUYMA_ALLOW_TIMESALE_PRICE_UPDATE=false
```

- `false`: 타임세일 및 할인 표시 상품은 변경 후보에서 제외합니다.
- `true`: 판매자 편집 화면에서 실제 상품 기본 가격을 다시 읽고, 그 가격을 기준으로 변경 예정가를 계산합니다.

타임세일 허용은 타임세일 종료나 BUYMA의 상품 정책에 영향을 줄 수 있으므로 필요한 경우에만 켜 주세요. 예약 실행에서는 이 값이 true일 때 별도 키보드 확인 없이 예약 작업에 포함합니다.

## 7. 예약 실행 프로그램

정해진 시간에 자동으로 가격 비교와 변경을 수행하려면 `BUYMA-Scheduler.exe`를 실행합니다. 이 창은 계속 켜 두어야 합니다. 예약 시간이 되면 자동으로 실행하고, 다음 예약까지 대기합니다.

`.env` 예시:

```env
BUYMA_SCHEDULE_TIMES=06:00,12:00,18:00,00:00
BUYMA_SCHEDULE_PRICE_DELTA=10
BUYMA_SCHEDULE_MAX_CHANGE=50
BUYMA_SCHEDULE_HEADLESS=true
```

- `BUYMA_SCHEDULE_TIMES`: PC 현지 시간 기준 실행 시각. 쉼표로 구분합니다.
- `BUYMA_SCHEDULE_PRICE_DELTA`: 경쟁 최저가보다 낮출 금액(JPY)
- `BUYMA_SCHEDULE_MAX_CHANGE`: 한 번에 인하할 수 있는 최대 금액(JPY)
- `BUYMA_SCHEDULE_HEADLESS`: true면 브라우저 창을 띄우지 않습니다.

예약 실행은 정해진 시간마다 전체 URL을 확인하고 변경 조건에 맞는 상품을 처리합니다. 같은 날짜와 시간의 작업이 중복 실행되지 않도록 실행 기록을 `data/scheduler_runs.json`에 저장합니다. 이미 실행 중인 예약 실행기가 있으면 두 번째 프로그램은 시작하지 않습니다.

예약 실행에 필요한 BUYMA 웹 로그인은 `.env`의 `BUYMA_LOGIN_ID`, `BUYMA_LOGIN_PASSWORD`를 사용합니다. CAPTCHA나 추가 인증이 나타나면 예약 작업은 해당 회차를 중단하고 로그에 남깁니다. 예약 실행 중에는 키보드 입력을 기다리지 않습니다.

Windows가 절전 모드이거나 PC가 꺼져 있으면 실행되지 않습니다. 자동 운영 중에는 PC가 켜져 있고 절전 모드가 꺼져 있어야 합니다. 메뉴형 프로그램과 예약 실행기를 동시에 실행하지 않는 편이 좋습니다.

프로그램이 예약 작업 도중 강제 종료되면 같은 날짜/시간 작업을 다시 보내지 않습니다. 이미 일부 상품의 요청이 접수됐을 수 있으므로 `logs/`와 `reports/`를 확인한 뒤 다음 예약 회차 또는 메뉴형 프로그램으로 이어서 확인합니다.

## 8. 결과 확인

- 화면: 실행 중 처리 상황과 요약
- `logs/`: 로그인, 페이지 조회, API 요청 및 오류 기록
- `reports/`: 실행별 CSV 보고서
- Google Sheets: 최신 결과, 전체 실행 보고서, 실제 적용 이력

가격 변경 이력은 `api 가격변경 시트 이력` 탭에서 확인합니다. 이 탭에는 BUYMA API 요청이 접수된 상품만 추가됩니다.

## 9. 문제가 생겼을 때

- Google Sheets를 읽지 못하면 서비스 계정 파일 경로와 스프레드시트 공유 권한을 확인합니다.
- BUYMA 로그인에 실패하면 `.env`의 로그인 ID/비밀번호와 추가 인증 여부를 확인합니다.
- API 요청이 거절되면 `logs/`의 HTTP 오류 응답과 CSV의 비고를 확인합니다.
- API 요청 접수 후 가격이 바로 보이지 않으면 BUYMA 판매자 화면에서 처리 상태를 확인합니다.
- 프로그램을 강제 종료한 경우에도 처리 완료된 상품 결과는 CSV에 중간 저장되어 있습니다.

## 10. 담당자에게 전달할 때

실제 `.env`, `config.yaml`, `secrets/` 파일에는 로그인 정보와 인증 토큰이 들어 있을 수 있습니다. GitHub에 올리지 말고, 전달할 때는 별도 보안 경로를 이용하세요.
